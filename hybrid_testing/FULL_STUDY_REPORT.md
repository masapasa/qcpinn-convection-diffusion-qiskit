## 1. Introduction and Motivation

### 1.1 The Industrial Problem

Czochralski (CZ) crystal growth is the dominant method for producing single-crystal silicon ingots used in semiconductor wafer manufacturing. A silicon seed crystal is slowly pulled from a molten silicon bath (the "melt") held in a rotating quartz crucible at approximately 1685–1750 K. The quality of the resulting crystal — defect density, oxygen concentration, resistivity uniformity — is directly controlled by the hydrodynamics and thermal structure of the melt during the pull process.

The melt flow is governed by a coupled system of axisymmetric, incompressible Navier-Stokes equations with strong buoyancy (Grashof number Gr = 8,000), rotation-driven swirl, and heat transfer (Prandtl number Pr = 28.463). The full system predicts five coupled fields over the (r, z) domain:

- **u_r** — radial velocity (m/s)
- **u_z** — axial velocity (m/s)  
- **u_θ** — azimuthal (swirl) velocity (m/s)
- **p** — pressure (Pa)
- **T** — temperature (K)

Conventional Computational Fluid Dynamics (CFD) solvers can resolve these fields accurately, but a single simulation at one set of operating conditions (one pull speed, one rotation rate, one crucible geometry) takes hours to days on a compute cluster. For real-time process control, furnace design optimization, or parametric studies, this is prohibitive.

### 1.2 The Proposed Solution

We train a **Hybrid Quantum–Classical Physics-Informed Neural Network (HQPINN)** as a surrogate model. The surrogate:
- Takes spatial coordinates (r, z) as input
- Produces all five flow fields as output in milliseconds
- Is trained on CFD simulation data with Navier-Stokes residuals embedded in the loss function
- Uses a 16-qubit variational quantum circuit as a feature-extraction layer, executed on real IBM quantum hardware during fine-tuning

This combines the expressivity of classical deep learning, the physical consistency of physics-informed training, and the novel feature representation of near-term quantum circuits.

### 1.3 Why Quantum Computing?

The quantum layer contributes 96 of the model's 126,021 parameters (0.076%). Its role is not to perform the primary computation — that remains classical — but to inject quantum features whose structure is qualitatively different from anything a purely classical linear layer can represent. Quantum circuits can produce correlations between inputs through entanglement that are exponentially hard to reproduce classically, potentially providing a compact, expressive feature set for smooth physical fields.

The honest answer to whether this helps requires an ablation study (replacing the quantum layer with an equivalent classical layer and comparing accuracy), which is identified as a key next step. The present work demonstrates the infrastructure, training pipeline, and IBM quantum hardware execution at scale.

## 3. Model Architecture

### 3.1 Overview

The model is implemented in PyTorch and consists of five sequential components:

```
Input (r, z)
    │
    ▼
Fourier Feature Encoding  [2 → 48 dims]
    │
    ▼
Coordinate Projector      [50 → 128 → 128]
    │
    ▼
ResidualMLP × 2           [128 → 128]
    │
    ├──────────────────────────────────────┐
    │                                      │
    ▼                                      ▼
to_quantum                           classical_skip
[128 → 64 → 16]                      [128 → 64]
π · tanh(·)                          Tanh
    │                                      │
    ▼                                      │
16-Qubit Quantum Circuit                   │
2 layers: RY + RZ + Rot + CZ              │
returns ⟨Z_i⟩ for i=0..15               │
    │                                      │
    ▼                                      │
LayerNorm(16)                              │
    │                                      │
    └──────────────┬───────────────────────┘
                   │
                   ▼
         Concatenate [64 + 16 + 2 = 82]
                   │
                   ▼
         Post Network [82 → 128 → 64 → 5]
                   │
                   ▼
         Hard Constraints:
         u_r = r · raw_0
         u_z = raw_1
         u_θ = r · raw_2
         p   = raw_3
         T   = raw_4
```

### 3.2 Component Details

**Fourier Feature Encoding**  
A fixed (non-trainable) random projection: B ∈ ℝ^{2×24} sampled as N(0, 6²). The encoding maps (r, z) to 48 dimensions:
`ff(x) = [sin(2π x B), cos(2π x B)]`
This gives the network explicit access to spatial frequencies up to ~15 cycles/unit-length, enabling sharp spatial gradients without relying solely on network depth to learn frequency content. The scale=6.0 was chosen to balance coverage of both low-frequency (large-scale flow structure) and high-frequency (boundary layer) features.

**Classical Encoder**  
- Layer 1: Linear(50, 128) + Tanh — combines raw (r,z) with 48-dim Fourier features
- Layer 2: Linear(128, 128) + Tanh
- ResidualMLP × 2: each block applies `h ← Tanh(h + W₂·Tanh(W₁·h))`, enabling gradient flow through depth without vanishing gradients

**To-Quantum Projection**  
Linear(128, 64) + Tanh + Linear(64, 16), followed by π·tanh(·) to scale outputs to [−π, π]. These 16 values become the rotation angles for the RY gates at the circuit input, encoding the classical latent representation into qubit states.

**16-Qubit Variational Quantum Circuit**  
The circuit has 2 layers. Each layer applies:
1. Data encoding: RY(θᵢ) on each qubit i, where θᵢ is the i-th element of the encoded input
2. Data re-upload: RZ(0.5·θ_{(i+layer) mod 16}) on each qubit — injects input information at each layer depth
3. Trainable rotation: Rot(φᵢ, θᵢ, ωᵢ) — the 3-parameter Euler rotation gate, with 3 × 16 = 48 trainable parameters per layer
4. Entangling: alternating CZ gates between even-odd and odd-even qubit pairs, plus a closing CZ between qubit 15 and qubit 0, creating a ring topology

Measurement: ⟨PauliZ⟩ expectation value on each of the 16 qubits, returning a 16-dimensional real vector.

Total quantum parameters: 2 layers × 16 qubits × 3 angles = **96 parameters**

**Classical Skip Connection**  
Linear(128, 64) + Tanh — a parallel path that bypasses the quantum circuit entirely. This ensures the post-network always has access to the full classical representation, preventing the quantum bottleneck from degrading performance.

**Post Network**  
Linear(82, 128) + Tanh + Linear(128, 64) + Tanh + Linear(64, 5) — the final mapping from the concatenated [skip || quantum || raw_coords] to the 5 output fields.

**Hard Physical Constraints**  
u_r and u_θ are multiplied by r at the output layer. This enforces the physical boundary condition that radial and azimuthal velocities must vanish on the axis of symmetry (r = 0) exactly, not approximately. This is a hard constraint built into the architecture, not learned.

## 4. Physics Loss

### 4.1 Governing Equations

The model is trained to satisfy the steady-state, axisymmetric, incompressible Navier-Stokes equations in cylindrical coordinates (r, z), nondimensionalised with the velocity scale V and length scale L:

**Continuity:**
```
∂(r·u_r)/∂r  +  r·∂u_z/∂z  =  0
```

**Radial momentum:**
```
u_r·∂u_r/∂r + u_z·∂u_r/∂z − u_θ²/r + p_coeff·∂p/∂r
  − (1/Re)·[∂²u_r/∂r² + (1/r)·∂u_r/∂r − u_r/r² + ∂²u_r/∂z²]  =  0
```

**Axial momentum:**
```
u_r·∂u_z/∂r + u_z·∂u_z/∂z + p_coeff·∂p/∂z
  − (1/Re)·[∂²u_z/∂r² + (1/r)·∂u_z/∂r + ∂²u_z/∂z²]
  − (Gr/Re²)·θ  =  0
```

**Swirl (angular momentum):**
```
u_r·∂u_θ/∂r + u_z·∂u_θ/∂z + u_r·u_θ/r
  − (1/Re)·[∂²u_θ/∂r² + (1/r)·∂u_θ/∂r − u_θ/r² + ∂²u_θ/∂z²]  =  0
```

**Energy:**
```
u_r·∂θ/∂r + u_z·∂θ/∂z
  − (1/(Pr·Re))·[∂²θ/∂r² + (1/r)·∂θ/∂r + ∂²θ/∂z²]  =  0
```

where θ = (T − T_min)/(T_max − T_min) is the dimensionless temperature, Re = 15, Pr = 28.463, Gr = 8,000, and p_coeff = 134,128.

### 4.2 Implementation

All spatial derivatives are computed via PyTorch automatic differentiation (`torch.autograd.grad` with `create_graph=True`), enabling second-order derivatives without finite differencing. The physics residuals form five scalar MSE losses, summed into a total physics loss.

**Quantum detachment:** During physics loss computation, the quantum layer's output is detached from the computation graph (`q_out.detach()`). This prevents the need for second-order gradients to propagate through the quantum statevector simulation, which would be computationally intractable. The physics loss thus only trains the classical path, while the quantum path is updated by the data loss.

**EMA loss weighting:** An exponential moving average of each residual term (β = 0.95) normalises the five physics loss components so no single equation dominates. The scaled total physics loss is: `L_phys / max(mean_EMA_weight, 1e-12)`.

Before committing to GPU compute, we ran a rapid architecture validation locally on a Mac Mini M4 with 24 GB unified memory.

- 8 qubits (instead of 16) — reduces statevector from 2^16 to 2^8 = 256 amplitudes

**Outcome:** The 8-qubit local model trained successfully, reaching a validation MSE of ~4.6×10⁻³ in 120 epochs. The architecture was confirmed correct and the full 16-qubit version was prepared for GPU training.

## 7. Stage 3 — IBM Quantum Hardware Fine-Tuning

### 7.1 Rationale

The model was pretrained using PennyLane's `default.qubit` simulator with `backprop` differentiation — a noiseless, exact statevector simulation. When the quantum circuit is executed on real IBM quantum hardware, two additional noise sources are present:

1. **Gate errors:** Each CZ and Rot gate has finite fidelity (~99.5% for single-qubit, ~99% for two-qubit gates on ibm_fez)
2. **Measurement errors:** Readout of qubit states has finite accuracy (~1–2% error per qubit)

These errors cause the real hardware expectation values ⟨Z_i⟩ to differ systematically from the simulated values. Without adaptation, the pretrained classical head (which was calibrated to clean simulated quantum features) will receive noisy inputs and produce degraded predictions.

The IBM fine-tuning stage addresses this by freezing the quantum circuit and retraining only the classical post-network head on a small number of calibration points, using real hardware outputs as the quantum features.

### 7.2 IBM Quantum Backend

| Property | Value |
|---|---|
| Backend | **ibm_fez** |
| Processor type | 156-qubit Eagle r3 |
| Queue at job start | 0 pending jobs |
| Measurement error mitigation | M3 twirling (enabled automatically) |
| Dynamical decoupling | Disabled |
| Shots per job | 4,096 |
| Instance | hybrid_qcpinn (flex plan) |

ibm_fez was selected over other available backends (ibm_kingston, ibm_pittsburgh, ibm_boston, ibm_miami) specifically because it had zero queue depth at the time of submission, ensuring minimal latency between job submission and execution.

After longer training with physics loss, the γ values would be expected to diverge more as the model learns which qubits contribute information relevant to each field.

## 9. Analysis of Physics Loss Degradation

### 9.1 Quantitative Impact

| Field | Best MSE (ep.20, no physics) | Final MSE (ep.400, full physics) | Degradation Factor |
|---|---|---|---|
| u_r | 1.93×10⁻⁶ | 1.79×10⁻⁴ | **93×** |
| u_z | 5.78×10⁻⁵ | 8.83×10⁻³ | **153×** |
| u_θ | 1.44×10⁻⁶ | 5.06×10⁻⁵ | **35×** |
| **p** | **4.62×10⁻⁵** | **0.100** | **2,165×** |
| **T** | **5.07×10⁻⁵** | **0.129** | **2,544×** |

### 9.2 Root Cause

The pressure coefficient of 134,128 creates a severe scale imbalance in the dimensionless Navier-Stokes momentum equations. Specifically:

- Velocity gradient terms scale as O(1/Re) = O(1/15) ≈ 0.067
- Pressure gradient terms scale as p_coeff = 134,128

The ratio is ~2,000,000:1. When the physics loss is computed, the gradient of the pressure residual with respect to network parameters is amplified by this coefficient, effectively overriding the data loss signal for the pressure field. The model learns to satisfy the momentum equation pressure terms at the expense of data accuracy.

The same instability affects temperature through the energy equation: even though the energy equation itself does not contain p_coeff directly, the coupling through the velocity fields (which are distorted by the pressure-momentum imbalance) propagates the degradation to temperature.

### 9.3 The Physics Loss Explosion at Epoch 280

At epochs 280–290, the total loss jumped to 10⁹–10¹⁴:

```
[0280/400] loss=1.0368e+09 data=5.0592e-02 phys=2.1591e+10
[0290/400] loss=1.1795e+14 data=4.9662e-02 phys=2.1481e+15
[0300/400] loss=5.5708e-02 data=4.8543e-02 phys=9.6150e-02
```

The data loss remained stable (~0.05) throughout, confirming the explosion was entirely in the physics residual. This type of event occurs when the model's predictions briefly satisfy the boundary conditions but violate the interior PDE residuals in a region with large gradients. The gradient clipping (max norm = 1.0) prevented the parameters from making catastrophically large updates, and the model recovered by epoch 300.

### 9.4 Recommended Fix

For future training runs, the physics weight should be reduced to 0.001–0.005 (rather than 0.05), and a per-field weighting should be applied to compensate for the pressure coefficient scale mismatch. Specifically, the pressure physics loss term should be weighted by 1/(p_coeff)² ≈ 5.6×10⁻¹¹ to bring it to the same scale as the velocity residuals.

## 12. Key Findings

1. **The data-only model (epoch 20) is the best for deployment.** It achieves val MSE = 1.58×10⁻⁴ with excellent accuracy on all five fields. Physics loss with the current weighting scheme (0.05) is counterproductive given the pressure coefficient scale mismatch.

2. **The H100 is well-suited for this workload.** The 2^16 statevector simulation via PyTorch autograd on CUDA is efficient, and the 80 GB VRAM provided ample headroom (only 4.3 GB used) on GPU 4 while 4× the memory was consumed by the VLLM workload on GPUs 0–3.

3. **500 IBM quantum circuits executed successfully on real hardware.** This is the core scientific result: 2,048,000 shots of 16-qubit circuit execution on ibm_fez, producing real PauliZ expectation values for the Czochralski melt flow prediction task. No quantum simulation errors or hardware failures occurred.

4. **The quantum layer's contribution is unquantified.** With 96/126,021 parameters (0.076%), an ablation study is essential to determine whether the quantum circuit provides unique information or whether the classical skip connection already captures the same features.

5. **IBM plan management requires attention.** Both flex plan instances (hybrid_qcpinn and qpinn_CG) were exhausted during the fine-tuning run. For future runs, ensure sufficient plan time is purchased before starting, or use a reserved plan for sustained quantum workloads.
